# InkMaiden — как устроена

Программа для Windows (один exe): окно на HTML/CSS/JS, вся работа с файлами, книгами, картинками и читалкой — на Rust (Tauri 2).

```
inkmaiden/
├─ app/                  программа: окно и команды для интерфейса
│  └─ src/  main.rs      состояние, Config.json, регистрация команд
│           devices.rs   подключённые читалки: наблюдатель USB, автосохранение, Readers/*.json, подробности с диска
│           usb.rs       диски Windows: метка, место, ревизия USB (= ядро Linux)
│           books.rs     «Книги»: поиск, реклама, своя обложка, части книги, обработка одной книги
│           comics.rs    «Комиксы»: оценка (параллельно, с памятью), предпросмотр, сравнение режимов, обработка
│           files.rs     каталог работ (обои, иконки сна), установка иконки сна с откатом, загрузка на читалку
│           webview.rs   WebView2Loader.dll внутри exe (распаковывается в %LOCALAPPDATA%\InkMaiden\runtime)
├─ crates/
│  ├─ pb-core/           общее: справочник моделей (data/models.json: экран, корпус, процессор, ОЗУ, батарея…),
│  │                     читалки и их папки, Config.json, файлы (запись с проверкой, резервная копия, сравнение папок),
│  │                     details.rs — что видно с диска читалки, library.rs — её библиотека (explorer-3.db, копия), задачи
│  ├─ pb-books/          книги: FB2, FB2.ZIP, EPUB, FB3, TXT → FB2; обложка; чистка от рекламы (правка XML на месте);
│  │                     edit.rs — своя обложка, части книги (просмотр и правка), название/автор/серия
│  ├─ pb-image/          страницы: сжатие, обрезка, цветокор, режимы, имитация экранов e-ink
│  └─ pb-comics/         архивы CBZ/CBR/CB7/ZIP/RAR/7Z, названия по шаблону, обработка папки
├─ ui/                   интерфейс
│  ├─ index.html, css/app.css
│  ├─ js/main.js         оболочка: разделы, текущая читалка, экран «Подключите читалку», окно выбора
│  ├─ js/covers.js       13 стилей обложек (перенос из «Мастерской») и правила категорий
│  ├─ js/upload.js       общее для «Книг» и «Комиксов»: источник с недавними папками, загрузка на читалку
│  ├─ js/bridge.js       мост для встроенных редакторов (текущая читалка, сохранение обоев)
│  ├─ js/modules/        device, books, comics, wallpapers, sleep (на основе editor.js), settings
│  └─ tools/             редакторы обоев и иконки сна — собираются tools/build_tools.py
├─ tools/                исходники редакторов «Мастерской» и правки поверх них (build_tools.py, sleep_im.js)
├─ dev/                  только для разработки: проверка интерфейса в браузере без сборки (mock.js)
├─ design/               иконка программы, утверждённый прототип
└─ build-support/        сборка под Windows из Linux (webview2-com-sys с отложенной загрузкой DLL)
```

## Данные
Рядом с exe (если папка закрыта для записи — `%APPDATA%\InkMaiden`):
```
Config.json            тема, папки, история, поведение, настройки разделов, текущая читалка (current)
Readers\PB743K3.json   читалка: модель, что видно по USB, папки на ПК и на читалке, прошивка, иконка сна, снимок подробностей
Readers\PB743K3.png    фото читалки из system\device<код>.ico (прозрачные поля срезаны)
PB743K3\Books  Comics  Manga  Wallpapers  Sleep_icons
```
Читалку узнаём по метке `system\config\inkmaiden.json` на ней (`{ "id": "PB743K3" }`). Вторая такая же модель — `PB743K3-2`.

## Текущая читалка
Одна на все разделы. Подключённая выбирается сама (из нескольких — прежняя текущая); ничего не подключено, но читалки есть —
окно выбора при запуске; читалок нет — экран «Подключите читалку». Сменить вручную — «Настройки» → читалка → «Сделать текущей».

## Добавить модель
Запись в `crates/pb-core/data/models.json` (код как на метке диска: PB**743K3** → `743K3`) или файл `models.json` рядом с exe —
он дополняет или заменяет записи по коду.

## Добавить раздел
1. Логика — свой крейт в `crates/`, без зависимостей от окна.
2. Команды — `app/src/<раздел>.rs`, зарегистрировать в `generate_handler!` (`main.rs`).
3. Экран — `ui/js/modules/<раздел>.js`: `{ id, title, hint, icon, mount(main, ctx), unmount(), drop(paths)? }`, вписать в `MODULES` (`main.js`).
   Текущая читалка — `ctx.cur()` (её папки `dirs`, `readerDirs`, профиль `reader`), настройки — `ctx.config` / `ctx.set(key, value)`.
4. Долгие операции: `app.jobs.start("id")` (новый запуск отменяет прежний), прогресс — событием, отмена — `job_cancel`.

## Проверить интерфейс без сборки
```
python3 tools/build_tools.py                       # после правок редакторов
python3 -m http.server 8765                        # из корня, открыть http://localhost:8765/ui/
                                                   # ?scene=none — читалок нет, ?scene=offline — окно выбора
```
Вне программы `ui/js/api.js` берёт ответы из `dev/mock.js` (данные комиксов — `dev/mock-data.json`, пересобрать:
`cargo run --release -p pb-comics --example mockdata -- /tmp/polka-demo dev/mock-data.json`).

## Сборка exe (из Linux)
```
cargo test --release -p pb-core -p pb-books -p pb-image -p pb-comics
cargo build --release --target x86_64-pc-windows-gnu -p inkmaiden
```
Нужны mingw-w64 и rust-std для `x86_64-pc-windows-gnu`. Результат — один `inkmaiden.exe`: WebView2Loader.dll
встроен и подгружается отложенно (`build-support/webview2-com-sys`, `app/src/webview.rs`). WebView2 в Windows 10/11 уже есть.

## Книга: порядок обработки
Чистка по исходной книге (номера находок считаны с неё; разделы, поправленные вручную, не удаляются) → правки частей
(в FB2 номера разделов пересчитываются с учётом удалённых) → название, автор, серия → обложка. TXT: данные → FB2 → обложка.

## Что не видно по USB
Версия прошивки, заряд батареи, свободная оперативная память — читалка не пишет их в файлы, доступные по USB.
Процессор, ОЗУ, ёмкость батареи — по справочнику модели; прошивку можно вписать вручную.
С 0.5.0 это закрывает модуль диагностики (см. ниже); без него — справочник и ручной ввод.

## Загрузки (0.5.0)
Один список на читалку: config `queue` = { id читалки: [{ id, src, dst, kind, label, added }] } (ui/js/queue.js).
`queue_check(device, items)` → `pb_core::files::plan`: каждый файл, путь на читалке (относительно корня, через `/`),
размер, состояние new / same (тот же размер) / changed / missing. `queue_run(device, files)` копирует по одному через
`copy_checked` (временный файл, сверка размера, замена), события `queue://progress`, задача `queue` в `jobs`.
Скорость запоминается в config `uploadSpeed` (скользящее среднее) — по ней «примерное время».

## Блокировка во время операций
`busy(el, текст)` — размыть и выключить блок (inert), одна плашка с текстом поверх; `lock(el)` — только выключить.
Книги и комиксы: при сканировании — один блок «Сканирование… N из M» на всё ниже строки папки; при сохранении
открыта только нижняя строка с ходом и «Остановить». `progress({stage, value, detail})` и `loading()` — общие полосы и заглушки.

## Безопасное извлечение
`device_eject`: отказ, если активны задачи `queue` или `details`; затем FlushFileBuffers → FSCTL_LOCK_VOLUME →
FSCTL_DISMOUNT_VOLUME → IOCTL_STORAGE_MEDIA_REMOVAL → IOCTL_STORAGE_EJECT_MEDIA (app/src/usb.rs).

## Диагностика
Windows (app/src/usb.rs `disk`): GetVolumeInformation, GetDiskFreeSpace, FSCTL_IS_VOLUME_DIRTY,
IOCTL_DISK_GET_LENGTH_INFO, IOCTL_DISK_GET_DRIVE_GEOMETRY_EX, IOCTL_STORAGE_QUERY_PROPERTY, SMART_GET_VERSION.
Читалка: crates/pb-core/data/diag.app — shell-скрипт, только чтение (/ebrmain/version.txt, /proc, /sys/class/power_supply,
/sys/block/mmcblk*/device, thermal, fb, dmesg), пишет system/inkmaiden/diag.txt блоками `@@@ раздел`.
`pb_core::diag::parse` → items { cat, label, value, source, level }. Новый модуль данных: добавить блок в скрипт и разбор
в `parse` (тест `script_runs_and_parses` гоняет скрипт на Linux).

## Комиксы: пересчёт и шаблоны
Смена режима, тонких настроек или читалки только помечает оценку устаревшей (`S.stale`) и отменяет идущую задачу `estimate`;
`comics_estimate_all` запускается кнопкой «Пересчитать» (и сам — один раз после сканирования). Окно «Как называть файлы»:
готовые шаблоны `pb_comics::names::templates()` + до 4 своих (config comics.myTemplates); пример — `comics_name_samples`
(`Plan::name_samples`, план не меняется).

## Кнопки
Вторичные кнопки — мягкая заливка без рамки; редкие действия собраны в `menuButton()` (ui.js): «Папка» в строке источника,
«Ещё» у комиксов, «Добавить» в загрузках, меню у поля пути в настройках.

## Страницы живут между переходами (0.6.0)
main.js держит по контейнеру `.page-host` на раздел и только прячет его (`hidden`); `mount` вызывается один раз, `unmount` —
при смене текущей читалки (все страницы строятся заново). «Настройки» строятся при каждом открытии. «Моё устройство» в меню нет —
открывается карточкой читалки `#cur`. Общая раскладка: `.page-head` сверху, `.actions` снизу (у редакторов — `.tool-head`/`.tool-actions`).

## Подключение
`UsbState.ejected` — извлечённые диски не трогаются (обращение снова подключило бы том), пока буква не пропадёт;
`UsbState.since` — время подключения, `Device.last_off` — время отключения. Прошивка: `diag::fw_token` по отчёту модуля
или по имени файла system/config/firmware/<версия>.json (видно и по USB); найденная записывается в `Device.firmware`.

## Иконка сна в «Загрузках»
Пункт `{ kind: 'sleep', work }`: проверка — `sleep_plan` (что и куда запишется), перенос — `sleep_install` с резервной копией.

## 0.6.5 — читалка после сброса
Метка system/config/inkmaiden.json стирается полным сбросом/форматированием. Если подключена читалка без метки, а такая модель
уже сохранена и не подключена (`needs_claim`), она не сохраняется сама: `devices_state.unknown[].candidates`, окно спрашивает,
`device_claim(root, id|null)` пишет прежнюю метку или заводит новую. Уже раздвоенные записи — `device_merge(from, into)`:
`files::merge_dirs` (одноимённые не перезаписываются), очередь загрузок переносится, метка переписывается, лишний профиль удаляется.

## 0.8.0 — единая запись на читалку и единый вид
Правило: на читалку пишет только раздел «На читалку» (`modules/uploads.js`, id в коде и в config — по-прежнему `uploads`,
ключ config `queue`). Остальные разделы готовят данные на компьютере и добавляют пункты.
- Пункты: файлы/папки `{ src, dst, kind }` и действия `queue.ACTIONS` — `sleep { work }` (sleep_install), `sleep-restore
  { stamp }` (sleep_restore), `diag` (diag_install), `diag-remove` (diag_remove). Действия одного семейства заменяют друг
  друга (последняя выбранная иконка; поставить/убрать модуль). Проверка: файлы — `queue_check`, иконка — `sleep_plan`,
  остальные — строка «изменение» (state `act`). Запись: сначала файлы (`queue_run`), затем действия по порядку.
- Убраны прямые записи: `work_put` (команда удалена), «Сохранить и поставить» и отложенная установка иконки при подключении
  (`install_pending` вызывается только из `sleep_install`, тот требует подключённую читалку), авто-удаление модуля после
  отчёта (`device_details` возвращает `diagAutoRemove`, UI сам добавляет пункт `diag-remove`), перенос старых копий old/
  при подключении и при открытии копий (`move_reader_backups` — только внутри установки/возврата иконки).
  Отложенная иконка из прежних версий (`Device.sleep.pending`) один раз превращается в пункт, `sleep_unpend` снимает отметку.
  Без «На читалку» пишется только метка system/config/inkmaiden.json (узнавание читалки) и она же при claim/merge/rename.
- Одна кнопка раздела: `queue.applyButton(ctx, prepare)` — `.btn.apply` (графит, справа в `.actions`, число ждущих);
  prepare добавляет готовое раздела, затем переход. Книги/комиксы — `upload.toQueue` (пустая папка → окно «Сначала
  сохраните»); редакторы — `opt.apply/opt.save/opt.queueWork/opt.menu` в editor.js (нижняя строка: путь · название ·
  «Работы ▾» · «Сохранить» · «На читалку»); «Моё устройство» — просто переход.
- Меню: группа «Подготовка» и отдельный пункт `.nav-apply`; подсказки разделов — в title. Текущий раздел — заливка и метка слева.
- Список «На читалку»: группы-карточки (действия; затем по папке на читалке), строка — значок, название, путь, «⋯»
  (папка на читалке / убрать); у группы — «⋯» для всех; длинные группы свёрнуты до 6 строк.
- Полосы «Сейчас/Станет» у комиксов — сплошные; тост больше не перехватывает щелчки (pointer-events: none).
